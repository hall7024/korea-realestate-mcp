# korea-realestate-mcp v0.1 설계

- 작성일: 2026-11-11
- 상태: 확정. ai-oss-main이 쓰고 ai-oss-support가 실측하고 리뷰했다. 사용자가 둘의 합의로 결정하도록 위임했다.
- 저장소: github.com/hall7024/korea-realestate-mcp. 저장소 생성, 공개, npm 배포는 사용자가 확인한 뒤에 한다.
- 실측 근거: `test/fixtures/live/NOTES.md`, `manifest.json`

## 1. 목표

사용자가 Claude에게 "이 집 전세 괜찮나?", "이 아파트 시세가 어떻게 되나?"라고 물으면, 국토교통부 실거래가 공개 데이터를 근거로 숫자를 답할 수 있게 한다.

- 주 사용자는 Claude Desktop이나 Claude Code에 MCP를 붙여 질문하는 개인이다. 공공데이터포털 인증키는 사용자가 직접 발급한다.
- 부 사용자는 같은 코어를 npm 라이브러리나 CLI로 쓰는 개발자다.
- 포트폴리오 목적: 외부 공공 API를 운영 품질로 감싸는 능력을 보여 준다. 키 처리, 오류 처리, 호출 한도, 테스트, 보안, 배포가 대상이다.

### v0.1 범위
- **조회**: 실거래가 13종의 원자료 조회(`search_deals`).
  - 이미 실측한 5종(AptTrade, AptRent, RHTrade2, RHRent, OffiTrade)은 정규화까지 확정한다.
  - 나머지 8종은 문서 기준 best-effort로 처리하고, 활용신청 후 받은 fixture로 확정한다.
- **분석**: 시세 요약과 전세가율. 아파트, 연립다세대, 오피스텔만 대상이다.
- **지역 해석**: 자연어 지역명을 조회 가능한 시군구 코드와 법정동으로 바꾼다. 2026-07 개편 이전의 옛 이름도 처리한다.
- **진단**: `doctor` 명령으로 13종의 활용신청 상태를 확인한다.
- **배포 형태**: 단일 npm 패키지로 라이브러리, CLI, stdio MCP 서버를 함께 제공한다.

### v0.1에서 하지 않는 것
- 건축물대장, 공시가격, 단독·다가구 분석 (v0.2)
- 원격 HTTP MCP 서버, 키 없이 쓰는 프록시
- 디스크 캐시, CSV 출력, `.mcpb` 번들
- 법령 연계

## 2. 사용 장면 (README 데모 기준)

1. "마포구 아현동 래미안푸르지오 84㎡ 최근 1년 시세 알려줘"
   - 흐름: `market_summary`(region "마포구 아현동", name, area 84)
   - 단지가 하나로 정해지면: 중앙값, 범위, 월별 추이, 최근 거래를 답한다.
   - 단지가 여럿이면: 후보 단지를 돌려준다.
2. "그 단지 전세가율은?"
   - 흐름: `jeonse_ratio`
   - 답: 같은 조건의 ㎡당 매매 중앙값 대비 ㎡당 전세 중앙값, 표본 수, 신뢰도.
3. "강서구 화곡동 빌라 59㎡ 전세 4억이면 높은 편이야?"
   - 흐름: `jeonse_ratio`(rh, deposit 4억, area 59)
   - 답: 입력 보증금 ÷ 추정 매매가를 %로, 근거 표본과 함께 낸다. 판단 문구는 넣지 않는다.

## 3. 접근 방식

| 안 | 내용 | 판단 |
|---|---|---|
| **A. 단일 패키지, 진입점 3개** | `src/core` + `src/mcp` + `src/cli`. 인자가 없으면 MCP 서버로 실행된다 | **채택**. 설치, 배포, 버전이 하나로 끝나고 `npx -y korea-realestate-mcp`로 MCP 등록이 끝난다 |
| B. 모노레포 3패키지 | core, cli, mcp를 따로 배포 | 2주 범위에 비해 관리 비용이 크다 |
| C. MCP 서버만 | 코어를 내부 모듈로만 둔다 | 라이브러리와 CLI 사용층을 잃는다 |

라이브러리 진입점(`korea-realestate-mcp`)은 MCP SDK를 불러오지 않는다. MCP와 CLI는 `bin`에서만 불러온다.

## 4. 서비스 13종

- 요청 주소: `https://apis.data.go.kr/1613000/{service}/get{service}`
- 활용신청은 서비스마다 따로 해야 한다.

| id | service | 종류 | 데이터셋 | 실측 |
|---|---|---|---|---|
| `apt-sale` | RTMSDataSvcAptTrade | 아파트 매매 | 15126469 | ✅ |
| `apt-sale-detail` | RTMSDataSvcAptTradeDev | 아파트 매매 상세 | 15126468 | ⏳ |
| `apt-rent` | RTMSDataSvcAptRent | 아파트 전월세 | 15126474 | ✅ |
| `presale` | RTMSDataSvcSilvTrade | 분양·입주권 | 15126471 | ⏳ |
| `rh-sale` | RTMSDataSvcRHTrade2 | 연립다세대 매매 | 15126467 | ✅ |
| `rh-rent` | RTMSDataSvcRHRent | 연립다세대 전월세 | 15126473 | ✅ |
| `sh-sale` | RTMSDataSvcSHTrade | 단독·다가구 매매 | 15126465 | ⏳ |
| `sh-rent` | RTMSDataSvcSHRent | 단독·다가구 전월세 | 15126472 | ⏳ |
| `offi-sale` | RTMSDataSvcOffiTrade | 오피스텔 매매 | 15126464 | ✅ |
| `offi-rent` | RTMSDataSvcOffiRent | 오피스텔 전월세 | 15126475 | ⏳ |
| `commercial-sale` | RTMSDataSvcNrgTrade | 상업업무용 매매 | 15126463 | ⏳ |
| `land-sale` | RTMSDataSvcLandTrade | 토지 매매 | 15126466 | ⏳ |
| `industrial-sale` | RTMSDataSvcInduTrade | 공장·창고 매매 | 15126470 | ⏳ |

`services.ts`에 서비스별 매핑을 둔다. 실측에서 서비스마다 필드명이 다른 것을 확인했다.
- `nameField`: aptNm, mhouseNm, offiNm 등 서비스마다 다르다.
- `areaField`, `areaKind`: 면적의 종류는 전용(exclusive), 연면적(floor_total), 대지(land), 거래면적(deal) 중 하나다.
- `priceField`: dealAmount 또는 deposit
- 도로명 필드의 대소문자: AptRent는 소문자(`roadnm`)를 쓴다.

MCP와 분석에서는 아파트 매매를 `apt-sale`만 쓴다. `apt-sale-detail`은 라이브러리와 `search_deals`의 원자료 조회에서만 노출한다. 이렇게 하면 사용자가 활용신청할 데이터셋 수가 줄어든다.

## 6. 데이터 모델

```ts
type DealKind = "sale" | "rent";
type AreaKind = "exclusive" | "floor_total" | "land" | "deal";

interface Deal {
  service: ServiceId;
  kind: DealKind;
  lawdCode: string;         // 시군구 5자리
  umd: string;              // 법정동 (umdNm)
  jibun: string | null;
  name: string | null;      // 단지·건물 이름
  area: number | null;
  areaKind: AreaKind;
  floor: number | null;
  buildYear: number | null;
  date: string;             // 계약일 YYYY-MM-DD
  price: number | null;     // 매매가 (원)
  deposit: number | null;   // 보증금 (원)
  monthlyRent: number | null; // 월세 (원)
  contractType: "신규" | "갱신" | null; // 공백이면 null
  direct: boolean;          // dealingGbn === "직거래"
  cancelled: boolean;       // cdealType === "O"
  houseType: string | null; // "연립" | "다세대" | "연립다세대"
  raw: Record<string, string>;
}
```

### 정규화 규칙
- **문자열 값**: 모든 값을 trim한다. 공백 한 칸(" ")이나 빈 값은 null로 바꾼다. 제어 문자를 지우고 200자로 자른다. 응답 텍스트는 신뢰하지 않는다.
- **금액**: `dealAmount`와 `deposit`은 만원 단위에 콤마가 있는 문자열이다. `monthlyRent`는 콤마 없는 숫자 문자열이다. 셋 다 원 단위 정수로 바꾼다.
- **날짜**: dealYear, dealMonth, dealDay를 YYYY-MM-DD로 합친다. 값이 빠진 레코드는 버리고, 몇 건 버렸는지 센다.

## 7. 클라이언트

### 키
- 환경변수 `DATA_GO_KR_SERVICE_KEY`만 읽는다. 도구 입력에는 키 필드가 없다.
- 정규화 순서:
  1. 앞뒤 공백을 지운다.
  2. `%[0-9A-Fa-f]{2}`가 있으면 한 번 디코딩한다.
  3. `URLSearchParams`로 한 번만 인코딩한다.
- 키가 없으면 호출하지 않고 바로 오류를 낸다.

### 입력 검증
API는 잘못된 입력에도 `200`, `000`, 0건을 돌려준다. 그래서 호출하기 전에 클라이언트가 검사한다.
- **LAWD_CD**: `regions.json`에서 `queryable`인 코드만 받는다. 옛 코드는 새 코드로 안내한다.
- **DEAL_YMD**: YYYYMM 형식이어야 하고, 2006-01 이후에서 KST 기준 이번 달까지만 받는다.
- **경로와 파라미터 이름**: 상수로 둔다. fixture와 대조하는 테스트를 둔다.

### 요청
- https 고정, `redirect: "error"`, 타임아웃 15초, `numOfRows=9999`
- 페이지는 "누적 건수 ≥ totalCount"이거나 빈 페이지가 나올 때까지 순회한다.
- 응답 본문의 `numOfRows`가 요청 값보다 작으면 그 값에 맞춰 순회한다.
- 응답 본문이 16MB를 넘으면 중단한다.

### 동시성과 재시도
- 동시에 보내는 요청은 프로세스 전체에서 최대 4건이다.
- 재시도는 HTTP 429, 5xx, 네트워크 오류, 게이트웨이 code 23에만 한다. 최대 3회, 지수 백오프에 지터를 더한다.
- 그 밖의 오류는 재시도하지 않는다.

### 오류 해석
HTTP 상태와 상관없이 본문을 먼저 읽는다.

| 응답 | kind | hint |
|---|---|---|
| 403 / 30 | `key_or_subscription` | "키가 틀렸거나, 데이터셋 N의 활용신청이 안 됐습니다(신청 후 반영까지 최대 1시간)." 같은 키로 다른 서비스가 한 번이라도 성공했다면 `not_subscribed`로 좁힌다. 프로세스 메모리에 기억한다 |
| 401 / 20 | `no_key` | 키 없음 |
| 22 | `daily_limit` | 일일 한도 초과 |
| 23 | `rate_limit` | 초당 한도 초과 |
| 31 | `expired` | 활용기간 만료 |
| 10 | `bad_request` | 파라미터 오류 |
| 그 밖 | `upstream` | — |

오류 객체에는 서비스, HTTP 상태, 게이트웨이 코드만 담는다. 원본 예외, URL, 본문은 담지 않는다.

### 월 단위 부분 실패
실패한 달은 `failures: [{ lawdCode, ym, kind }]`에 담고, 나머지 결과는 그대로 쓴다. 모든 요청이 같은 이유로 실패하면 그 오류를 올린다.

### 예산
- 계산: 예상 호출 수 = 서비스 수 × 시군구 코드 수 × 개월 수 (`numOfRows=9999`라 보통 한 달에 한 페이지)
- 한 번의 도구 호출에서 이 값이 80을 넘으면 실행하지 않는다. 대신 법정동이나 구로 좁히거나 기간을 줄이라고 안내한다.
- 예: 단일 구, 13개월, 매매·전세 = 26건이다. 수원시처럼 4개 구로 펼쳐지는 지역은 104건이라 구를 고르라고 안내한다.

### 캐시
- 키는 `(service, lawdCode, ym)`다.
- 이번 달과 지난달은 1일, 그 전 달은 30일 동안 쓴다. 실패는 캐시하지 않는다.
- `raw`를 뺀 Deal만 저장한다. 크기는 바이트로 추정하고, 상한 64MB의 LRU로 관리한다.

## 8. 지역 해석

### `data/regions.json`
code.go.kr의 법정동코드 전체자료로 만든다.
- `sigungu`: `{ code, name, sido, queryable }`
  - `queryable=false`는 하위 구가 있는 시(수원시, 화성시 등)와 시도 단위다.
  - 시에는 `children`(구 코드 목록)을 둔다.
- `umd`: 시군구 코드별 법정동 이름 목록
- `aliases`: 옛 이름에서 새 코드로 가는 별칭(1:N 포함). 폐지된 코드의 법정동 이름을 현재 코드의 법정동과 맞춰 생성한다.
  - 예: 인천 중구 → 제물포구, 영종구
  - 예: 광주광역시 북구 → 전남광주통합특별시 북구
  - 예: 화성시 → 4개 구

### `resolveRegion(query)`
- 받는 입력: "서울 강남구", "강남구", "마포구 아현동", "아현동", "수원시", 옛 시도 이름, 시도 약칭, 5자리 시군구 코드, 10자리 법정동코드
- 결과: `{ matches: Region[] }`. 각 Region은 `{ lawdCodes: string[], label, umd?: string }`이다.
- 후보가 여럿이면 조회하지 않고 후보만 돌려준다.
- 옛 코드나 옛 이름은 새 코드로 바꾸고, `note`에 "2026-07 개편으로 ○○로 바뀜"이라고 적는다.

### 조회 원칙
2026-07 행정구역 개편 지역도 새 코드로만 조회한다. API가 과거 거래까지 새 코드로 다시 묶어 두었다(2020-01 실측). 옛 코드로는 0건이 나온다.

## 9. 분석 (apt, rh, offi)

### 기간
- `months: 12`는 KST 오늘을 기준으로 계약일이 최근 12개월 안인 거래를 뜻한다. API 호출은 13개 달이다.
- 실거래 신고 기한이 30일이라 최근 두 달은 건수가 덜 잡힌다. 그래서 월별 추이에서 이 두 달에는 `partial: true`를 붙인다.

### 기본 제외
- 해제된 거래는 뺀다.
- 직거래는 뺀다. 옵션 `includeDirect`로 포함할 수 있고, 몇 건을 뺐는지는 항상 표시한다.

### 단지 지정 (`name`)
- 공백을 무시한 부분 일치로 찾은 다음 `(umd, jibun, 정규화한 이름)`으로 묶는다.
- 묶음이 두 개 이상이면 분석하지 않고 단지 후보(이름, 법정동, 지번, 건수)를 돌려준다.
- 출력에는 매칭된 단지 이름과 지번을 항상 적는다.

### 면적 필터
| 범위 | 허용 오차 |
|---|---|
| 단지 지정 | ±3% |
| 아파트, 법정동 범위 | ±10% |
| 빌라·오피스텔 | ±15% |

### `marketSummary`
- 결과 항목: 건수, 중앙값, 최소·최대, 사분위 범위(Q1~Q3), ㎡당 중앙값, 최근 계약일, 월별 `{ ym, count, median | null, partial }`, 최근 거래 5건
- 월 표본이 3건 미만이면 그 달의 중앙값은 null이다.

### `jeonseRatio`
- 계산: ㎡당 전세 중앙값 ÷ ㎡당 매매 중앙값. 매매와 전세는 같은 필터와 기간을 쓴다.
- 전세 표본 정의: 월세가 0이고, 갱신 계약이 아닌 것. contractType이 공백인 계약은 포함한다.
- 매매와 전세 중 어느 쪽이든 5건 미만이면 값을 내지 않고 이유를 돌려준다.
- `deposit`을 입력하면 다음을 숫자로만 낸다.
  - 추정 매매가 = ㎡당 매매 중앙값 × area
  - 입력 보증금 ÷ 추정 매매가 (%)
  - area가 없으면 이 계산은 하지 않는다.

### 신뢰도
| 등급 | 조건 |
|---|---|
| 높음 | 단지 범위이고, 매매·전세 각 10건 이상이며, 최근 6개월에 각 3건 이상 |
| 보통 | 그 밖에 각 5건 이상. 법정동 범위는 최대 "보통"이다 |

결과에는 판정 기준을 함께 적는다.

### 판단 문구
"위험", "적정" 같은 판단은 넣지 않는다. 숫자, 표본, 기준만 낸다. README에는 "참고 자료이며 계약이나 투자 판단의 근거가 아님"을 적는다.

## 10. MCP 도구

- 모든 도구는 `annotations: { readOnlyHint: true, openWorldHint: true }`를 단다.
- 입력은 zod로 검증한다(enum, 길이·범위 제한).
- **출력**: content 텍스트에 모델이 답하는 데 필요한 숫자를 압축한 표로 모두 넣는다. `structuredContent`에도 같은 내용을 넣는다. `raw`는 넣지 않는다.
- **오류**: `isError: true`로 돌려주고 hint를 단다.
- **출처 줄**: 결과 끝에 출처와 조회 시각을 한 줄 넣는다. 예: "출처: 국토교통부 실거래가 공개자료(공공데이터포털), 조회 2026-11-11 22:40 KST"
- **결과 구분**: "조회는 정상, 해당 기간 거래 0건"은 오류와 다른 문구로 쓴다.

| 도구 | 입력 | 출력 |
|---|---|---|
| `resolve_region` | `query` (≤ 50자) | 후보 목록 |
| `search_deals` | `propertyType` (apt, rh, sh, offi, presale, commercial, land, industrial), `dealType` (sale, rent), `region`, `months`(1–24, 기본 3) 또는 `from`/`to`, 선택: `name`, `areaMin/Max`, `includeCancelled`, `limit`(≤ 50, 기본 20) | 최신순 거래 목록, 전체 건수, 제외 건수, 실패한 달 |
| `market_summary` | `propertyType` (apt, rh, offi), `region`, 선택: `name`, `area`, `months`(기본 12), `includeDirect` | 9장 시세 요약 |
| `jeonse_ratio` | `propertyType` (apt, rh, offi), `region`, 선택: `name`, `area`, `deposit`, `months`(기본 12) | 9장 전세가율 |

- `region`에는 법정동이 들어갈 수 있다("마포구 아현동"). 그래서 `umd` 파라미터는 따로 두지 않는다.
- `area` 설명에 "전용면적 ㎡ (34평형 ≈ 84㎡)"라는 힌트를 넣는다.
- `presale`과 `sh` 같은 미실측 서비스는 결과에 "정규화 미검증"이라고 표시한다.
- 도구 설명은 짧게 쓰고 바꾸지 않는다.

## 12. 보안

### 비밀값 처리
- `maskSecrets(text)`는 키의 원문과 인코딩된 형태를 `***`로 바꾼다. 로그, 오류, 도구 결과, CLI 출력에 모두 적용한다.
- 원본 예외 메시지는 내보내지 않는다. undici의 "Failed to parse URL from …"이 URL 전체를 담기 때문이다. 이것을 테스트로 고정한다.
- 로그는 stderr로만 내보내고, `(service, lawdCode, ym, page, status)`만 남긴다.

### 의존성
- 런타임 의존성은 `@modelcontextprotocol/sdk`(1.24 이상, CVE-2025-66414), `zod`, `fast-xml-parser`(최신)만 둔다. 버전을 고정한다.
- XML 파서 설정: `parseTagValue: false`, `isArray: name === "item"`, `processEntities`는 기본 엔티티만 허용, DOCTYPE은 거부한다.

### 저장소
- 비밀값 검사: `.gitleaks.toml`에 serviceKey 규칙을 넣는다.
- ESLint: typescript-eslint strict와 eslint-plugin-security를 쓰되 `detect-object-injection`은 끈다.
- CI: 타입 검사, 린트, 테스트, gitleaks, Semgrep OSS, zizmor
- 그 밖: CodeQL 기본 설정, Dependabot(npm, github-actions), SECURITY.md
- workflow: `permissions: contents: read`, 액션은 SHA로 고정한다.
- 배포 workflow는 npm trusted publishing(provenance)으로 둔다. 실행은 사용자가 확인한 뒤에 한다.

### README 안내
- 설정 예시에 버전을 고정한다(`korea-realestate-mcp@0.1`).
- Claude Desktop 설정 파일에 키가 평문으로 남는다는 점을 안내한다.

## 13. 테스트

- **파서**:
  - 실측 fixture 5종, 오류 응답 8종
  - 1건짜리 응답(실측분에서 item 하나만 남겨 만든다)
  - 0건(`<items/>`), 공백 한 칸 값, `&amp;`
- **정규화**: 금액, 날짜, 해제, 직거래, houseType 3종, 서비스별 필드 매핑
- **키**: Decoding·Encoding 키 정규화. 마스킹은 원문과 인코딩된 형태를 모두 지운다.
- **클라이언트(가짜 fetch)**:
  - 페이지 순회(조용히 잘리는 상한 포함)
  - 재시도 대상과 비대상
  - 30을 미신청으로 좁히는 경우
  - 부분 실패, 예산 초과, 입력 검증(옛 코드, 미래 달), 캐시 신선도, 응답 크기 상한
- **보안**: 키와 URL이 오류 메시지, 로그, 도구 결과, CLI 출력에 나오지 않는다.
- **지역**: 단일 결과, 겹치는 이름, 법정동만 입력, 하위 구가 있는 시, 옛 이름(1:N), 코드 입력
- **분석**: 중앙값, 사분위, 면적 허용 오차, 단지 후보, 월별 partial과 null, 전세 표본 정의, deposit 계산, 신뢰도
- **MCP**: SDK의 메모리 전송으로 도구 4개를 호출한다. 입력 오류, 후보 반환, 0건 문구, 정상 결과를 확인한다.
- **CLI**: 하위 명령 출력과 TTY 도움말
- **실측**: `LIVE=1`이고 키가 있을 때만 돈다. CI에서는 제외한다.

## 16. 구현하면서 바뀐 점 (2026-11-11)

- **Node 22 이상**: Node 20은 2026-04에 지원이 끝났고, vitest 5도 22 이상을 요구한다. CI는 22와 24에서 돈다.
- **MCP 결과**: `structuredContent`를 빼고 텍스트만 보낸다. `outputSchema` 계약 없이 보내면 토큰만 약 4.5배 늘기 때문이다. 구조화된 객체가 필요하면 라이브러리 API를 쓴다.
- **서버 instructions**: "판단하지 말 것" 대신 "숫자와 표본·기준을 함께 전하고, 계약 판단은 사용자 몫이며 필요하면 등기부·전문가 확인을 권할 것"으로 바꿨다. 사용자가 "높은 편이야?"라고 물었을 때 모델이 답을 피하지 않게 하려는 것이다. 도구 출력에는 여전히 판단 문구가 없다.
- **전세가율 보강**: deposit과 area를 주면 추정 전세가, 입력 보증금 ÷ 추정 전세가, 비교 전세 중 분위를 함께 낸다. 전세 표본에서 뺀 월세·갱신 건수와 지역 범위의 단지 수도 표시한다.
- **지역**:
  - 후보마다 그대로 다시 넣을 수 있는 `query` 값을 둔다.
  - 10자리 법정동코드를 법정동까지 해석한다.
  - "광주시"는 시도(전남광주통합특별시)보다 경기 광주시를 먼저 찾는다.
  - 행정동(역삼1동)과 줄임말(강남, 동탄)은 한 번 더 바꿔서 찾는다.
  - 읍·면을 지정하면 그 아래 리 전체를 포함한다.
- **클라이언트** (리뷰 반영):
  - 쪽 크기 9999로 받은 결과가 모자라면 1000으로 다시 받는다. 그래도 모자라면 `incomplete`로 실패한다.
  - 레코드를 하나도 해석하지 못하면 `schema` 오류로 실패한다.
  - 게이트웨이 20(키 없음과 접근 거부 구분), 12, 29, 32를 따로 분류한다.
  - 전역 오류가 나면 남은 요청을 보내지 않는다.
  - 같은 달을 동시에 요청하면 한 번만 호출한다.
  - 캐시 신선도는 받은 시점을 기준으로 판단한다.
- **실패 안내**: 서비스 하나가 모든 달에서 실패하면 그 서비스와 데이터셋을 알리는 오류로 올린다. 일부 달만 실패하면 서비스마다 한 번씩 안내한다.
